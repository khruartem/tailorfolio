# Tailorfolio

> Один профессиональный профиль. Отдельное представление для каждой роли.

[Русский](README.md) | [English](README.en.md)

Tailorfolio — open-source full-stack платформа для создания мультиязычного резюме-портфолио и его публикации по одной ссылке.

Сейчас проект находится на этапе формирования продуктового и инженерного фундамента. Описанные ниже возможности запланированы, но ещё не реализованы.

## Проблема

Профессиональная информация обычно распределена между классическим резюме, карьерными платформами, GitHub, личным сайтом и отдельными описаниями проектов. Отправлять всё это работодателю неудобно, а одно универсальное резюме редко одинаково хорошо подходит для разных ролей и языков.

Tailorfolio должен стать единым источником профессиональных данных, на основе которого пользователь сможет создавать разные представления портфолио под конкретные роли, вакансии, аудитории и языки.

## Идея продукта

Пользователь создаёт профессиональный профиль с опытом, проектами, навыками, образованием, контактами и полезными ссылками. Затем на основе профиля формирует несколько представлений, выбирает их содержание и оформление, добавляет переводы и публикует каждое представление по уникальному URL.

Примеры будущих представлений на основе одного профиля:

- Frontend Developer;
- Full-stack Developer;
- System Analyst;
- англоязычное портфолио для международных вакансий.

## Планируемый MVP

- регистрация и аутентификация;
- редактор профессионального профиля;
- опыт, проекты, навыки, образование, контакты и ссылки;
- несколько представлений на основе одного исходного профиля;
- настройка видимости и порядка разделов;
- русский и английский контент;
- готовые темы и ограниченная визуальная кастомизация;
- состояния черновика, предпросмотра, публикации и снятия с публикации;
- уникальная публичная ссылка;
- адаптивные и доступные публичные страницы;
- базовая SEO-разметка и метаданные для социальных сетей;
- автоматические тесты, CI/CD и production-наблюдаемость.

Точные границы MVP поддерживаются в [дорожной карте](docs/roadmap.md). Новые идеи не попадают в активный scope автоматически.

## Учебные цели

Tailorfolio также является production-like учебным проектом для практики full-stack разработки:

- архитектура React-приложения на TypeScript;
- Feature-Sliced Design на frontend;
- разработка API на Node.js;
- моделирование данных и миграции PostgreSQL;
- аутентификация, авторизация и web-безопасность;
- unit, integration, component и end-to-end тестирование;
- Docker и воспроизводимое локальное окружение;
- CI/CD, логирование, метрики и готовность к инцидентам;
- архитектурная документация и принятие технических решений.

## Предварительное техническое направление

Технологии и их конкретные версии будут окончательно зафиксированы через Architecture Decision Records в соответствующих итерациях дорожной карты.

| Область | Предварительное направление |
| --- | --- |
| Репозиторий | monorepo на pnpm workspaces и Turborepo |
| Frontend | React, TypeScript, Vite |
| Frontend-архитектура | Feature-Sliced Design |
| Работа с серверными данными | TanStack Query |
| Формы и валидация | React Hook Form и Zod |
| Backend | Node.js, TypeScript, Fastify |
| База данных | PostgreSQL и Drizzle ORM |
| API-контракт | OpenAPI |
| Тестирование | Vitest, Testing Library, Playwright |
| Инфраструктура | Docker Compose и GitHub Actions |

Feature-Sliced Design применяется только на frontend. Backend планируется как модульный монолит и будет использовать границы, соответствующие серверным бизнес-модулям, а не копировать frontend-структуру.

В документе [«Структура репозитория»](docs/repository-structure.md) описаны начальная и целевая структуры, ответственность каталогов и правила зависимостей.

## Дорожная карта

Разработка ведётся по зафиксированной схеме «теория → проектирование → практика → проверка»:

1. продуктовый фундамент;
2. доменная модель и системный дизайн;
3. инженерный фундамент и инициализация monorepo;
4. сквозные вертикальные срезы;
5. основная функциональность продукта;
6. тестирование, безопасность, доступность и производительность;
7. развёртывание, наблюдаемость и production-релиз;
8. open-source оформление и финальная архитектурная защита.

После каждой итерации в дорожной карте фиксируются результат, выполненные проверки, обнаруженные пробелы и ссылки на связанные pull request и документы. Сроки можно двигать, но изменение цели или обязательного scope проекта требует отдельного Change Request.
